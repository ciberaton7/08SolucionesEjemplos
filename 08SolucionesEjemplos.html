Solución: Modularidad (Básico)

El Reto: Crear un namespace Geometria, con una clase Cuadrado y utilizarla en el Program.cs.

Análisis para el estudiante: Observen cómo el uso del namespace aísla nuestra clase. Si otra persona crea otra clase llamada Cuadrado en otra carpeta, no habrá conflictos porque nuestro cuadrado vive exclusivamente dentro de Matematicas.Geometria.

Geometria.cs
Program.cs
// --- Archivo: Geometria.cs ---
namespace Matematicas.Geometria
{
    public class Cuadrado 
    {
        // Método público que recibe el lado y retorna el área
        public double CalcularArea(double lado) 
        {
            return lado * lado;
        }
    }
}

// --- Archivo: Program.cs ---
// Importamos el módulo para que C# sepa dónde buscar
using Matematicas.Geometria;

class Program
{
    static void Main()
    {
        // Instanciamos la clase de nuestro módulo
        Cuadrado miCuadrado = new Cuadrado();
        double resultado = miCuadrado.CalcularArea(5.5);
    }
}

Solución: Modularidad (Complejo)

El Reto: Separar la lógica universitaria en módulos de Academico y Usuarios, e interactuar con ambos.

Análisis para el estudiante: Aquí vemos una simulación real de arquitectura de software. Pasamos el objeto Materia (que pertenece a un módulo) como parámetro al método de un Docente (que pertenece a otro módulo diferente). El Main actúa como el coordinador central.

Sistema.cs
Program.cs
// --- Archivo: Sistema.cs ---
namespace Unifranz.Academico
{
    public class Materia {
        public string Nombre;
    }
}

namespace Unifranz.Usuarios
{
    // Necesitamos importar Academico para que el Docente
    // reconozca el tipo de dato "Materia"
    using Unifranz.Academico;

    public class Docente {
        public void AsignarNota(Materia m, int nota) {
            Console.WriteLine($"Nota {nota} subida a {m.Nombre}");
        }
    }
}

// --- Archivo: Program.cs ---
using Unifranz.Academico;
using Unifranz.Usuarios;

class Program {
    static void Main() {
        Materia prog = new Materia() { Nombre = "Programación" };
        Docente profe = new Docente();
        profe.AsignarNota(prog, 100);
    }
}

Solución: Modificadores (Básico)

El Reto: Clase Termometro con propiedad privada y validación en el bloque set (cero absoluto).

Análisis para el estudiante: Esta es la esencia del Encapsulamiento. Noten cómo la variable _temperatura lleva un guion bajo por convención (para variables privadas). La Propiedad pública actúa como el filtro de seguridad gracias a su if y a la palabra mágica value.

Termometro.cs
public class Termometro
{
    // La variable real donde se guarda el dato (Protegida)
    private double _temperatura;

    // La Propiedad pública por donde el usuario ingresa el dato
    public double Temperatura
    {
        get 
        { 
            // Retornamos el valor real
            return _temperatura; 
        }
        set 
        { 
            // 'value' representa lo que se intentó guardar desde el Main
            // Validamos que no viole las leyes físicas (-273.15 °C)
            if (value >= -273)
            {
                _temperatura = value; // Autorizado
            }
            else
            {
                Console.WriteLine("Error: Inferior al cero absoluto.");
            }
        }
    }
}

Solución: Modificadores (Complejo)

El Reto: Clase UsuarioPlataforma con cambio de contraseña seguro.

Análisis para el estudiante: A veces, no usamos Propiedades (get/set) para todo. Para contraseñas, no queremos un get público que permita a cualquiera leer la clave. Usamos un método explícito (CambiarClave) que exige un proceso lógico (validación cruzada) antes de alterar el dato privado.

UsuarioPlataforma.cs
public class UsuarioPlataforma
{
    public string Correo { get; set; } // Propiedad automática
    
    // La contraseña es estrictamente privada. No hay 'get' público.
    private string _password;

    // Constructor: Así le damos una clave inicial al nacer
    public UsuarioPlataforma(string claveInicial)
    {
        _password = claveInicial;
    }

    // Método seguro para alterar el estado interno
    public void CambiarClave(string claveAntigua, string claveNueva)
    {
        // Comparamos la clave que ingresó el usuario con la real
        if (claveAntigua == this._password)
        {
            this._password = claveNueva;
            Console.WriteLine("Clave actualizada con éxito en la BD.");
        }
        else
        {
            Console.WriteLine("Operación denegada: Clave incorrecta.");
        }
    }
}

Solución: Herencia (Básico)

El Reto: Clase base Electrodomestico y clases hijas (Refrigerador, Licuadora).

Análisis para el estudiante: Fíjense en la eficiencia del código. Escribimos el código de encendido una sola vez en el padre, pero ambas clases hijas lo saben usar a la perfección. Es el principio de la reutilización (Don't Repeat Yourself).

Electrodomesticos.cs
// Clase Padre (Base)
public class Electrodomestico
{
    public string Marca { get; set; }
    public int ConsumoWatts { get; set; }

    public void Encender()
    {
        Console.WriteLine($"Encendiendo equipo {Marca}...");
    }
}

// Clase Hija 1: Absorbe todo y añade su propiedad de frío
public class Refrigerador : Electrodomestico
{
    public double TemperaturaMinima { get; set; }
}

// Clase Hija 2: Absorbe todo y añade su propiedad de motor
public class Licuadora : Electrodomestico
{
    public int Velocidades { get; set; }
}

Solución: Herencia (Complejo)

El Reto: Nóminas. Clase Empleado. Clase Vendedor usa base y override.

Análisis para el estudiante: Este es un diseño arquitectónico completo. El constructor de Vendedor necesita pedir 3 datos, pero delega dos de ellos hacia arriba usando : base(). Luego, usa override para aplicar la matemática de la comisión, sobreescribiendo el método virtual del padre.

Planilla.cs
public class Empleado
{
    public string Nombre;
    protected double SalarioBase; // Protected: visible para hijas

    public Empleado(string nom, double salario) { 
        Nombre = nom; SalarioBase = salario; 
    }

    // "virtual" permite que los hijos alteren este cálculo
    public virtual double CalcularPagoMensual() {
        return SalarioBase;
    }
}

public class Vendedor : Empleado
{
    public double MontoVentas;

    // Pasamos 'nom' y 'sal' hacia el constructor padre
    public Vendedor(string nom, double sal, double ventas) : base(nom, sal) 
    {
        MontoVentas = ventas;
    }

    // "override" para cambiar la fórmula (añadir 10% comisión)
    public override double CalcularPagoMensual() {
        return SalarioBase + (MontoVentas * 0.10);
    }
}

Solución: Abstracción

El Reto: Clase abstracta Animal. Método concreto Dormir(). Método abstracto HacerSonido().

Análisis para el estudiante: Observen el método HacerSonido(); en la clase base. ¡No tiene llaves! Es un mandato. Obliga a que tanto el Gato como el Perro abran sus propias llaves en la parte inferior y escriban la implementación.

Fauna.cs
// Plantilla base. No se puede instanciar con 'new'
public abstract class Animal
{
    // Código real compartido por todos los animales
    public void Dormir()
    {
        Console.WriteLine("Zzz...");
    }

    // Contrato obligatorio para cada especie. (Termina en ;)
    public abstract void HacerSonido();
}

public class Perro : Animal
{
    // El compilador exige usar override aquí
    public override void HacerSonido()
    {
        Console.WriteLine("Guau! Guau!");
    }
}

public class Gato : Animal
{
    public override void HacerSonido()
    {
        Console.WriteLine("Miau...");
    }
}

Solución: Interfaces (Reto Final)

El Reto: Interfaz IGuardable implementada por clases dispares (DB y Archivo).

Análisis para el estudiante: Esta es la cima de la arquitectura en C#. Una Interfaz jamás tiene modificadores public adentro de ella. Simplemente firma el "Qué". Abajo, las dos clases son radicalmente distintas, pero ambas cumplen el contrato de guardado.

Persistencia.cs
// El Contrato Maestro
public interface IGuardable
{
    // Ni public, ni virtual, ni cuerpo. Solo la firma.
    void GuardarDatos(string informacion);
}

// Clase de Servidor que firma el contrato
public class BaseDeDatos : IGuardable
{
    public void GuardarDatos(string informacion)
    {
        Console.WriteLine($"Generando Query SQL para: {informacion}");
        Console.WriteLine("Conectando al servidor y guardando...");
    }
}

// Clase Local que también firma el contrato
public class ArchivoTexto : IGuardable
{
    public void GuardarDatos(string informacion)
    {
        Console.WriteLine($"Abriendo log.txt...");
        Console.WriteLine($"Escribiendo texto en disco: {informacion}");
    }
}
